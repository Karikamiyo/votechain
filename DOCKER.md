# VoteChain — Docker setup

Запуск всего проекта одной командой.

## Что внутри

Четыре сервиса в `docker-compose.yml`:

| Сервис | Порт | Назначение |
|--------|------|------------|
| `hardhat` | 8545 | Локальный блокчейн (hardhat node) |
| `deployer` | — | Однократно деплоит контракт, потом завершается |
| `backend` | 8000 | Django + DRF + web3.py |
| `frontend` | 80 | Собранный React + nginx с прокси на бэк |

## Требования

- **Docker Desktop** (Windows/macOS) или Docker + Docker Compose (Linux). Уже стоит ✅
- **MetaMask** в браузере — для голосования

## Запуск

В корне проекта:

```bash
docker compose up --build
```

Первая сборка займёт 3–5 минут (скачиваются базовые образы Node, Python, nginx и ставятся все зависимости). Последующие запуски — секунд 20.

В логах ты увидишь четыре потока: hardhat (длинный список аккаунтов), deployer (короткое сообщение про деплой), backend (Django стартует) и frontend (nginx стартует).

Когда увидишь в логах:
```
votechain-backend  | Starting development server at http://0.0.0.0:8000/
```
— всё готово.

Открой:
- **http://localhost** — сам сайт
- **http://localhost:8000/api/owner/** — проверка бэка (должен вернуть JSON)

## Остановка

`Ctrl+C` в окне, где запущен compose. Если запускал в фоне (`-d`):

```bash
docker compose down
```

## Полный сброс (когда хочешь начать с чистого блокчейна)

```bash
docker compose down -v
```

Флаг `-v` удаляет тома, в том числе `hardhat-artifacts`, где лежат ABI и состояние. После этого следующий `docker compose up` снова задеплоит контракт с нуля.

## Архитектура запуска

```
       ┌──────────┐
       │ hardhat  │ ← порт 8545 (MetaMask и фронт подключаются сюда)
       └────┬─────┘
            │ healthcheck
            ▼
       ┌──────────┐
       │ deployer │ ← деплоит контракт → завершается
       └────┬─────┘
            │ depends_on (completed_successfully)
            ▼
       ┌──────────┐
       │ backend  │ ← порт 8000 (читает ABI из общего тома)
       └────┬─────┘
            │ depends_on
            ▼
       ┌──────────┐
       │ frontend │ ← порт 80 (nginx, прокси /api/ → backend)
       └──────────┘
```

## Если что-то сломалось

**Порт 80 занят** (часто на Windows из-за IIS или Skype):
В `docker-compose.yml` поменяй `"80:80"` на `"8080:80"`. Сайт станет доступен на http://localhost:8080.

**Порт 8000 занят** (другой Django-сервер):
В `docker-compose.yml` поменяй `"8000:8000"` на `"8001:8000"`. Это влияет только на доступ к API напрямую — фронт ходит через nginx-прокси и его это не затрагивает.

**Порт 8545 занят** (старый hardhat запущен):
Останови старый процесс через диспетчер задач или из терминала `Ctrl+C`.

**MetaMask: "Internal JSON-RPC error" при голосовании после `docker compose down -v`**:
Блокчейн начал жизнь с нуля, но MetaMask хранит старый счётчик транзакций. Лечится: MetaMask → Settings → Advanced → "Clear activity tab data".

**Контейнеры падают / висят в "starting"**:
Посмотри логи: `docker compose logs hardhat` (или `backend`, `deployer`). Чаще всего проблема видна сразу.

## Проблема: "SocketError: other side closed" при компиляции контракта

Если сборка падает на компиляции контракта — это значит, hardhat не может
скачать компилятор Solidity (solc) с серверов soliditylang.org. Соединение
режет файрвол, антивирус или нестабильная сеть.

В текущей версии компиляция вынесена из этапа сборки в рантайм (deployer
повторяет до 5 раз). Если и это не помогает:

**Решение 1 — отключить антивирус/файрвол на время первой сборки.**
Часто виноват именно он (особенно Касперский, Avast). После первого успешного
скачивания solc кешируется, и проблема исчезает.

**Решение 2 — скомпилировать контракт локально и положить рядом.**
Если у тебя локально работает `npx hardhat compile` (вне Docker), то папка
`artifacts/` и `cache/` уже созданы. Можно временно убрать их из `.dockerignore`,
чтобы они скопировались в образ, и тогда компиляция в Docker не понадобится:

1. Локально выполни: `npx hardhat compile`
2. В `.dockerignore` закомментируй строки `artifacts/` и `cache/` (поставь `#`).
3. Пересобери: `docker compose build --no-cache hardhat deployer`

**Решение 3 — сменить сеть.** Мобильный интернет / другой Wi-Fi часто решает
проблему, если виноват провайдер или корпоративный файрвол.
