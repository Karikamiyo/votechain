# VoteChain — Система электронного голосования на блокчейне

Учебный проект, демонстрирующий **прозрачное и неизменяемое голосование** на основе
блокчейна. Каждый голос — это транзакция в блокчейне, подписанная самим избирателем.
Подделать, удалить или изменить голос невозможно: это гарантируется смарт-контрактом,
а не доверием к серверу.

## Как это работает

Проект состоит из четырёх частей:

```
┌─────────────┐         REST API          ┌──────────────┐      web3.py      ┌──────────────┐
│  Frontend   │ ───── чтение данных ─────► │   Backend    │ ───── читает ────►│   Hardhat    │
│   (React)   │                            │   (Django)   │   и пишет в       │   node       │
│             │ ◄──── списки, статусы ──── │              │   контракт        │ (блокчейн)   │
└──────┬──────┘                            └──────────────┘                   └──────┬───────┘
       │                                                                             │
       │            vote() — голос подписывается напрямую в MetaMask                 │
       └─────────────────────────────────────────────────────────────────────────► │
                                                                            VoteChain контракт
```

**Ключевая идея архитектуры:**

- **Чтение данных** (список голосований, кандидаты, результаты, статусы) идёт через
  **бэкенд** — это быстро и удобно.
- **Действия администратора** (создать голосование, добавить избирателя, закрыть
  голосование) идут через **бэкенд** — он подписывает их ключом владельца контракта.
- **Голосование (`vote`)** идёт **напрямую из MetaMask** в блокчейн, минуя бэкенд.
  Это и есть суть проекта: голос подписывает сам избиратель своим приватным ключом.
  Никто — даже владелец сервера — не может проголосовать за другого человека.

**Технологии:**

| Часть | Технологии |
|-------|-----------|
| Смарт-контракт | Solidity 0.8.24, Hardhat |
| Бэкенд | Python, Django, Django REST Framework, web3.py |
| Фронтенд | React, TypeScript, Vite, Tailwind CSS, wagmi, RainbowKit |
| Инфраструктура | Docker, Docker Compose, nginx |

## Запуск через Docker

### Шаг 1. Распакуй проект

Структура должна выглядеть так:

```
votechain/
├── api/                      # Django-приложение (REST API)
├── contracts/                # Смарт-контракт VoteChain.sol
├── scripts/                  # Скрипт деплоя
├── frontend/                 # React-приложение
│   ├── Dockerfile
│   ├── nginx.conf
│   └── ...
├── docker/                   # Вспомогательные скрипты для контейнеров
│   ├── backend-entrypoint.sh
│   ├── deployer-entrypoint.sh
│   └── healthcheck.js
├── votechain_backend/        # Настройки Django
├── docker-compose.yml        # ← главный файл, описывает все сервисы
├── Dockerfile.backend
├── Dockerfile.hardhat
├── hardhat.config.js
├── requirements.txt
└── package.json
```

### Шаг 2. Открой терминал в папке проекта

### Шаг 3. Запусти командой

```powershell
docker compose up --build
```

Что произойдёт:

1. **Сборка образов** (первый раз — 3–8 минут)
2. **Запуск сервисов** в правильном порядке:
   - `hardhat` — поднимает локальный блокчейн на порту 8545;
   - `deployer` — деплоит смарт-контракт и завершается;
   - `backend` — запускает Django на порту 8000;
   - `frontend` — запускает nginx с сайтом на порту 80.

> ⚠️ **Сборка падает на этапе компиляции** с ошибкой
> `HH502` или `SocketError: other side closed` — это блокировка сети.
> См. раздел [Проблема с компилятором](#проблема-с-компилятором) ниже. Эта проблема
> решается включением vpn/прокси

### Шаг 4. Проверка

После сообщения:
```
votechain-backend  | Starting development server at http://0.0.0.0:8000/
```
— Можно открывать в брауере:

- **http://localhost** — сам сайт (список голосований);
- **http://localhost:8000/api/owner/** — проверка бэкенда. Должен вернуть JSON:
  ```json
  {
    "owner": "0xf39Fd6e51aad88F6F4ce6aB8827279cffFb92266",
    "contract_address": "0x5FbDB2315678afecb367f032d93F642f64180aa3",
    "chain_id": 31337
  }
  ```

Можно переходить к
[настройке MetaMask](#настройка-metamask).

### Остановка

В терминале с логами нажми **`Ctrl+C`**. Затем для полной очистки:

```powershell
docker compose down
```

Контейнеры удалятся, но образы и данные сохранятся — следующий запуск будет быстрым.

### Повторный запуск

```powershell
docker compose up
```

### Полный сброс (чистый блокчейн)

```powershell
docker compose down -v
```
Флаг `-v` удаляет тома с данными. После этого следующий запуск заново задеплоит
контракт.

> ⚠️ После сброса с `-v` нужно очистить кэш MetaMask — см.
> [Частые проблемы](#частые-проблемы).

## Проблема с компилятором

Если при сборке появляются следующие сообщения:
```
Error HH502: Couldn't download compiler version list.
```
```
Caused by: SocketError: other side closed
```
```
RUN npx hardhat compile ... exit code: 1
```

### Причина

Hardhat при компиляции контракта скачивает компилятор Solidity (`solc`) с серверов
`binaries.soliditylang.org`. Это скачивание часто **блокируется**:

- провайдером интернета;
- университетским / корпоративным файрволом;
- антивирусом (Kaspersky, Avast и др. с функцией «проверки HTTPS»).


### Решение — Включить прокси/VPN 

Самый надёжный способ. Включи любой прокси или VPN на компьютере, затем запусти
сборку заново:
```powershell
docker compose down
docker compose up --build
```

> После того как компилятор скачался **один раз**, он сохраняется в образе.
> Прокси можно выключить — повторные запуски (`docker compose up` без `--build`)
> работают без него.

## Настройка MetaMask

Чтобы голосовать, нужно подключить кошелёк MetaMask к локальному блокчейну.

### Шаг 1. Установка MetaMask

Расширение для браузера: https://metamask.io/download/

### Шаг 2. Добавь сеть Hardhat

1. В настройках расширения перейти в "Сети" и добавить новую со следующими параметрами:
   - **Network name / Имя сети:** `Hardhat Local`
   - **RPC URL:** `http://localhost:8545`
   - **Chain ID / ID блокчейна:** `31337`
   - **Currency symbol / Символ валюты:** `ETH`
   - Block explorer URL — оставь пустым.

    

> ℹ️ Если MetaMask показывает красное сообщение «Этот ID блокчейна уже используется
> сетью Hardhat Local» - сеть уже добавлена. Необходимо найти ее в списке сетей и
> переключиться вручную

### Шаг 3. Импортируй тестовые аккаунты

Импортируй **два** аккаунта:

**Администратор** (владелец контракта, может создавать голосования):
```
0xac0974bec39a17e36ba4a6b4d238ff944bacb478cbed5efcae784d7bf4f2ff80
```

**Избиратель** (обычный пользователь):
```
0x59c6995e998f97a5a0044966f0945389dc9e86dae88c7a8412f4603b6b78690d
```

> Для удобства можно переименовать прямо в расширении

У каждого аккаунта будет баланс **10000 ETH** — это виртуальные тестовые деньги
для оплаты газа. Если баланс 0 — значит, выбрана не та сеть, переключись на
«Hardhat Local».

## Как пользоваться

Полный сценарий от создания голосования до подсчёта голосов.

### 1. Подключи кошелёк администратора

1. Открой http://localhost.
2. В MetaMask выбери аккаунт **Admin** и сеть **Hardhat Local**.
3. На сайте нажми «Подключить кошелёк» → выбери MetaMask → подтверди подключение.
4. В шапке появится ссылка **«Админка»** — она видна только владельцу контракта.

### 2. Создай голосование

1. Перейди в «Админка» → «Создать голосование».
2. Введи название (например, «Выборы старосты 2026») и минимум 2 кандидата.
3. Нажми «Создать». Подожди пару секунд — бэкенд отправит транзакцию в блокчейн.
4. Новое голосование появится в списке.

### 3. Добавь избирателей в белый список

Голосовать могут только адреса из белого списка (whitelist).

1. В админке у нужного голосования нажми «Управлять».
2. Скопируй адрес аккаунта **Voter** из MetaMask (клик по имени аккаунта — адрес
   скопируется).
3. Вставь его в поле «Добавить избирателя» и нажми «Добавить».

### 4. Проголосуй

1. Переключи MetaMask на аккаунт **Voter**. (Ссылка «Админка» на сайте пропадёт —
   это нормально, Voter не администратор.)
2. На главной открой голосование (клик по карточке).
3. Выбери кандидата → «Проголосовать».
4. MetaMask покажет окно подтверждения транзакции → нажми «Confirm» / «Подтвердить».
5. Через пару секунд появится «Голос принят!» с хешем транзакции.
6. Обнови страницу — счётчик голосов вырос, в результатах появилась полоска.


## Справочник API

Все эндпоинты доступны с префиксом `/api/`. Базовый адрес: `http://localhost:8000`
(через Docker — также доступны как `/api/...` через nginx-прокси на порту 80).

| Метод | URL | Описание |
|-------|-----|----------|
| GET | `/api/owner/` | Адрес владельца контракта |
| GET | `/api/elections/` | Список всех голосований |
| POST | `/api/elections/` | Создать голосование |
| GET | `/api/elections/<id>/` | Данные голосования |
| GET | `/api/elections/<id>/candidates/` | Список кандидатов |
| POST | `/api/elections/<id>/whitelist/` | Добавить избирателя |
| POST | `/api/elections/<id>/close/` | Закрыть голосование |
| GET | `/api/elections/<id>/results/` | Результаты |
| GET | `/api/elections/<id>/voters/<address>/status/` | Статус избирателя |

> Голосование (`vote`) намеренно отсутствует в API — оно выполняется напрямую
> через MetaMask, чтобы голос подписывал сам избиратель.

### Примеры

```powershell
# Список голосований
curl http://localhost:8000/api/elections/

# Создать голосование
curl -X POST http://localhost:8000/api/elections/ -H "Content-Type: application/json" -d "{\"title\": \"Выборы 2026\", \"candidates\": [\"Иванов\", \"Петров\"]}"

# Добавить избирателя в whitelist
curl -X POST http://localhost:8000/api/elections/0/whitelist/ -H "Content-Type: application/json" -d "{\"userAddress\": \"0x70997970C51812dc3A010C7d01b50e0d17dc79C8\"}"
```

## Частые проблемы

### «node не является внутренней или внешней командой» (при запуске без Docker)
Не перезапущен терминал после установки Node.js. Закрой и снова открой терминал
(и VS Code, если используешь).

### Сборка Docker падает на компиляции контракта (`HH502` / `SocketError`)
Блокировка сети. Включи прокси/VPN. Подробно — в разделе
[Проблема с компилятором](#проблема-с-компилятором).

### `container votechain-hardhat is unhealthy`
Нода не прошла проверку здоровья. Обычно лечится пересборкой:
```powershell
docker compose down -v
docker compose up --build
```

### В логах бесконечно идёт `eth_chainId (5)... (6)...`
Это **не ошибка**, а логи проверки здоровья ноды

### http://localhost не открывается (но :8000 работает)
Порт 80 занят
В `docker-compose.yml` у сервиса `frontend` поменяй `"80:80"` на `"8080:80"`,
пересобери докер. Сайт будет на http://localhost:8080.


### Баланс аккаунта в MetaMask = 0
Выбрана не та сеть. Необходимо переключиться на «Hardhat Local». На правильной сети у тестовых
аккаунтов 10000 ETH.


## Тестовые аккаунты

Hardhat при каждом запуске создаёт одни и те же 20 аккаунтов. Вот первые два,
которые используются в проекте:

| Роль | Адрес | Приватный ключ |
|------|-------|----------------|
| **Admin** (owner) | `0xf39Fd6e51aad88F6F4ce6aB8827279cffFb92266` | `0xac0974bec39a17e36ba4a6b4d238ff944bacb478cbed5efcae784d7bf4f2ff80` |
| **Voter** | `0x70997970C51812dc3A010C7d01b50e0d17dc79C8` | `0x59c6995e998f97a5a0044966f0945389dc9e86dae88c7a8412f4603b6b78690d` |

> ⚠️ Эти ключи **публично известны** (они захардкожены в Hardhat). Использовать их
> можно только в локальной тестовой сети. **Никогда** не отправляй на эти адреса
> реальные средства в настоящих сетях — они будут потеряны.
